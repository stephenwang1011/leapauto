# 蓝牙钥匙现场测试

适用：`3.3.34`（versionCode `3003034`）签名 Release。用户在 `3.3.33`、`3.3.34` 实测均遇到认证结果码 `9`；3.3.34 已交付并复测，当前车辆认证问题尚未解决。

## 已收到的 3.3.34 结果

- 钥匙同步、SM2 派生、GATT 连接、通知订阅、MTU 协商和两次分片写入均完成；扫描信号为 `-39 dBm`。
- `PROTOCOL_SELECTED code=8 detail=2` 表示使用默认版本 8，不能据此认定该车必须使用版本 9。
- 311 字节完整认证报文写入后，车辆返回 26 字节事件报文，并在认证阶段报告结果码 `9`。未出现 `AUTHENTICATED`，也未发送车锁指令。
- 用户已确认零跑官方 App 和提供的 `base.apk` 对应参考客户端都能连接其 C16。参考客户端成功时使用完整认证（`AA AE`）还是缓存凭证快速重连（`AA EE`），尚未确认；扫描后点击连接也可能使用快速重连。
- 当前问题集中在认证兼容性，不能以重复同步、写入成功或单元测试通过宣称已修复。后续取证需与成功流程对照，继续禁止导出真实证书、身份字段、密钥及原始认证报文。

源码、smali 和官方 native 库的对照结果见 `API/BLUETOOTH_PROTOCOL.md` 的 2026-09-15 排障补充。下列正常与被动配置流程是后续验收目标，不代表本车已通过。

## 后续诊断改动（源码，尚未交付）

- 设置页默认隐藏“蓝牙数字钥匙”，本次进入设置后点击顶部“设置”标题 5 次才显示入口；离开设置页或退出登录后重新隐藏。隐藏只影响入口，已启用的后台服务和通知管理入口保持原有行为。
- 手动连接读取当前扫描记录中的版本；缺少广播版本时，仅复用账号、车辆、蓝牙地址和证书匹配的已保存版本，再无依据才回退 8。认证与绑定保存使用同一份解析结果。
- 新增 `AUTH_CERTIFICATE_STRUCTURE`、`AUTH_TEXT_STRUCTURE`、`AUTH_CIPHER_STRUCTURE`、`AUTH_CONFIGURATION`，记录本次实际构造的字段数、文本与签名长度、加密长度和发送配置标志，不记录字段内容。
- 证书原账号／设备与当前身份是否相同，以匹配位记录。参考协议会替换这两个字段，因此“不匹配”本身不证明证书失效。
- 这些改动用于修复确定的版本选择差异并提高排障能力；结果码 `9` 是否消失，仍需目标 C16 复测。四个后台与被动控制开关继续默认关闭。

## 准备

- 安装本轮签名 Release，确认“我的”中的版本号；登录并选择要测试的车辆。
- 在有网络时打开“蓝牙钥匙”，点“同步钥匙”。SM2 车辆应显示“SM2 钥匙已就绪”。
- 本轮新增证书与请求设备身份绑定，升级后旧缓存需要重新同步。测试前退出原版的蓝牙连接，避免两个客户端同时占用车辆连接。
- 开启手机蓝牙，按系统提示授予附近设备权限。Android 11 及以前还需要扫描定位权限与系统定位开关。
- 车辆证书按账号和车辆加密保存；现场扫描、认证、蓝牙锁控本身不需要云端控车请求。
- 后台配置四个开关均默认关闭：后台蓝牙钥匙、靠近自动解锁、远离自动锁车、微动开关控锁。微动仅在车辆协议 minor >= 9 时可编辑，未知能力不得假定支持。

## 正常流程

1. 打开“我的（设置） → 蓝牙钥匙”。主界面不展示蓝牙入口、状态或通道选择。
2. 在车辆附近点“扫描车辆”。扫描最长 20 秒，列表展示可连接设备和信号强度。
3. 选择车辆，观察连接、服务发现、通知订阅、认证各阶段，最终应显示“已认证”。
4. 在蓝牙管理页操作上锁或解锁。首次操作按提示设置操作密码，并确认本次动作。
5. 记录车锁实际动作与应用显示。应用只在收到匹配动作事件后显示车辆确认；超时显示结果未确认。
6. 每条控制完成后连接会释放。下一次操作前点“重新连接”，完成新认证后再确认动作。

爱车页全部控车按钮保持云端控制；蓝牙测试必须在设置页的蓝牙管理界面进行。
现场验证时，先确认状态为“已认证”，再点击管理页的车锁操作；连接、认证或发送过程中车锁按钮不可用。
关闭管理页会取消待确认的蓝牙操作；蓝牙操作若失败，不会自动改走云端。
蓝牙指令已经发出且仍在等待车辆确认时，主界面车锁操作会提示“当前车锁操作尚未完成”，不会同时发出云端指令。
进入后台时，未启用后台配置会断开手动连接；已明确保存并确认的后台配置由前台服务维持连接并在断线后完整认证重连。强制停止、划掉最近任务、厂商省电限制、权限或通知限制都可能终止后台驻留，不能保证自动恢复。

## 被动配置流程

1. 在“蓝牙钥匙”管理页保持车辆已认证，编辑四个开关；草稿不会被显示为车辆已应用。
2. 点击“保存设置”，先通过操作 PIN 和配置确认弹窗；保存只提交当前草稿，不会直接执行上锁或解锁。
3. 观察“等待车辆同步”。只有配置命令 `cmdId=3` 完整写入并收到当前请求匹配的 `0`/`00` 回执，才显示“车辆已同步”。
4. 关闭总开关会生成全关闭目标并显示“关闭待同步”；在车辆确认前不能认为自动操作已经关闭。确认后后台服务才停止。
5. 已同步且后台未运行时，可点击“恢复连接”；恢复只连接、认证并同步保存配置，不发送手动锁控动作。

必须分别验证：四开关默认全关、启用自动解锁、启用自动锁车、minor >= 9 微动能力、minor < 9/未知微动禁用、重复保存需要新回执、关闭待同步、连接断开后的恢复，以及账号/车辆切换清理。车辆靠近/远离距离、实体微动开关动作、后台通知和厂商限制均需在目标车辆及系统上实测；应用不使用 RSSI 换算距离，也不主动发送手机自动锁控命令。

## 现场排障

| 现象 | 观察位置 | 回传证据 |
| --- | --- | --- |
| 无法扫描或没有车辆 | 权限/蓝牙提示、SCAN_STARTED / SCAN_FAILED / SCAN_FINISHED | 诊断记录与手机 Android 版本；记录当时是否靠近车辆 |
| 一直连接中或断开 | GATT_STATE 的系统状态码、TIMEOUT 所在阶段 | 诊断记录；是否曾显示“已认证” |
| 钥匙解析失败 | KEY_DERIVATION_FAILED | 1001 格式、1002 曲线、1003 公钥点、1005 密钥派生等稳定分类 |
| 认证失败或无响应 | PROTOCOL_SELECTED、NOTIFICATIONS_RESULT、MTU_RESULT、RX_FRAME、VEHICLE_REJECTED | 记录协议来自广播、默认回退还是已保存绑定；保留失败阶段与结果码，不回传证书或原始报文 |
| 有写入但车锁不动作 | TX_ACK、COMMAND_EVENT、COMMAND_CONFIRMED 或 COMMAND_UNCONFIRMED | 诊断记录和肉眼观察到的实际车锁状态 |

在管理页展开“连接诊断”，使用复制或系统分享导出记录。记录仅在内存保留最近 120 条，
包含相对耗时、协议类型、报文长度、系统状态码及失败阶段；不会导出 VIN、蓝牙地址、设备名称、
证书、密钥、PIN 或原始报文。切换账号/车辆和退出应用会清理相关内存记录。

## 证据边界

协议实现经过解包源码与 smali 对照，SM2/SM3/SM4 合成向量由独立密码库交叉复核。
单元测试、编译与签名验证不能替代车辆现场验收。首次现场测试需要分别记录扫描、认证、上锁、
解锁、失败后重新连接的结果；不以 GATT 写入成功推断车辆已完成动作。
